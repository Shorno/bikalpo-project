# Dynamic property QR poster

The property details sidebar uses the supplied portrait navy/orange design.
Property name, location, full actual property ID and QR are live component props.
The QR uses the existing permanent property token route, not a listing ID.
No database or route changes are needed.

Preview and PDF download share PropertyQrPoster. On demand, the browser captures
the SVG at 2048 x 3072 pixels and embeds the lossless PNG in a single A4 PDF,
centered with print margins and without stretching or cropping. The existing
pdf-lib dependency is lazy-loaded. QR uses high error correction and a
four-module quiet zone. Download is disabled
until an absolute URL is available, and failures have a retryable message.
The QR origin uses NEXT_PUBLIC_APP_SUBDOMAIN_URL when configured, otherwise
the current browser origin. Without that configuration, local downloads target
the local host; verify the production URL before printing for public use.

Artwork provenance: to-let-property-poster-template.png was generated by editing
the user-supplied codex-clipboard-9f0439cc-0510-43fc-96e2-f77982973943.png.
The edit removed only sample property name, location, QR pixels and badge text
to make a reusable background, preserving the supplied composition and branding.
The original generation retains C2PA metadata. This is raster background artwork
(1024 x 1536); the PDF is a flattened, print-resolution image, not editable text.

Verification: two component tests pass; synthetic desktop (1024px), mobile
(360px) and long Bengali/English-name fixtures render without page overflow.
Long identity text wraps into two lines rather than distorting glyphs.
Name and location type scale with content length; the full property ID is
preserved. An empty location displays "Location available on property page".
The browser waits for fonts before capturing. Dynamic Bengali text is baked
into the PDF, so the print workstation does not need those fonts installed.
Browser fixture verification generated a valid one-page A4 application/pdf file
with Bengali/English identity and checked the missing-artwork error path.
Poppler-rendered PDF was visually checked against the preview.
An authenticated download click and physical phone/printed QR scan remain
manual acceptance checks. No business records were modified for verification.
Repository-wide TypeScript still reports pre-existing shared UI React type
errors; no poster-file diagnostics were reported in the check.
